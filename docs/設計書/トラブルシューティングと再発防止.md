# トラブルシューティングと再発防止策

AI解説機能の実装およびレビュー過程で判明した重大なアーキテクチャ上のバグと、その再発防止策を記録する。

## 1. TaskCompletionSource (TCS) と WPF Window の競合によるクラッシュ
*   **事象**: `OverlayWindow` をキャプチャ時に閉じるとき、`Close()` を呼んだ直後に結果を返却すると、`Closed` イベントが先に発火してしまい結果が握り潰される。また、呼び出し元の `App.xaml.cs` 側で `tcs.Task` を待った後に再度 `overlay.Close()` を呼ぶと `InvalidOperationException` が発生する。
*   **対策**: `Window` は自身で `Close()` を行い、必ず結果を送信（`Snipped?.Invoke`）した**後**に `Close()` を呼ぶ。呼び出し元は `await` 後に絶対に `Close()` を呼んではならない。

## 2. CancellationTokenSource の破棄競合と例外
*   **事象**: ウィンドウが閉じられたイベント（`resultWindow.Closed`）の中で即座に `opCts.Dispose()` を呼んだため、まだHTTP通信中のスレッドがトークンを参照して `ObjectDisposedException` でクラッシュする。
*   **対策**: `Closed` イベント内では `Cancel()` のみを呼び、`Dispose()` は非同期メソッド（`RunCaptureAsync`）の `finally` ブロックで通信が完全に終了した後に実行する。

## 3. High-DPI とマルチモニター座標系の混同
*   **事象**: `OverlayWindow` が渡したWPF論理座標（DIP）を、物理ピクセルを要求する `Screen.FromPoint` に渡したため、150%等のスケーリング環境で誤ったモニター情報を取得し、ウィンドウが画面外に吹き飛ぶ。
*   **対策**: 座標計算はすべて論理座標（DIP）で統一する。モニター境界（`Bounds`）を判定する場合は、DPIスケールで割ってDIPに変換してから比較・代入する。

## 4. WPFレイアウトエンジン：StackPanel内のScrollViewerの自壊
*   **事象**: 縦 `StackPanel` の中に `ScrollViewer` を配置したため、手動リサイズで `MaxHeight` を解除した瞬間に `StackPanel` の無限測定が働き、スクロールバーが消滅して下部のテキストが読めなくなる。
*   **対策**: `StackPanel` ではなく、`Grid` のスター行（`<RowDefinition Height="*"/>`）に `ScrollViewer` を配置する。

## 5. UIのリグレッション（コピー・Escキー）
*   **事象**: `TextBlock` を使ったことでテキスト選択・クリップボードコピーができなくなった。また、Escキーでのウィンドウクローズが削除されていた。
*   **対策**: 表示エリアには `TextBox`（`IsReadOnly="True"`）を採用してテキスト選択を可能にし、キーダウンイベントでEscキーをハンドリングする。
